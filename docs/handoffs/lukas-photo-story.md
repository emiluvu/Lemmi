## Implemented within Lukas's activity slice

Extends `photo_album` through the existing create/reduce/project/system-input
functions. No additional activity ID, backend, session store or model adapter.
Album views use Photo Story; scene collections retain Explore pictures. Talk now
accepts an approved caption without private discussion context. With neither
description available, Talk is disabled and Just look/navigation/Finish remain.

`preparePhotoStoryTurn` is a pure server-consumed content helper, exported by
`@lemmi/activities` with local `PhotoStoryInput`, `PhotoStoryFact` and
`PhotoStoryPreparation` types. These are content types, not a new network API.
It takes current shared profile/session/activity/context, confirmed scoped asset
availability and reviewed facts. It returns bounded caption/profile grounding and
reviewed opening/follow-up instructions, or patient waiting text for silence and
unclear recognition. No model response is generated by this helper.

Facts are limited to the current photo's tags and eligibility. Inputs must agree
on profile, session, profile/policy revision and effective support. Paused/ended,
Just look and unavailable media cannot prepare conversation. Output binds profile,
privacy/policy, session generation/lease, activity revision, photo and asset IDs.
The host must compare those again before provider calls and text/audio publication.
This is not authentication, semantic validation, a capture grant or output approval.

Participant words are transient and unconfirmed, separate from caregiver facts.
Never persist/log helper inputs/outputs or put them in ActivityView/events/journals.
No permission, excerpt, preference, biography or summary changes are implemented.
Reviewed instructions request brief adult-respectful turns, one question, no
recognition quiz or fabricated personal history, and patience with repetition.
Quiet requests acknowledgment/caption without an unsolicited question. These
instructions alone do not prove model grounding or semantic safety.

## Inspected dependencies and remaining owner handoffs

At inspection, `origin/main` is `53c7a5f`. Working server adapters were inspected
on the unmerged `origin/backend-deploy` at `04d050e`; no server files were copied.

- `createOpenRouterAdapter` and `ChatInput` support only string system/history/text.
  There is no image content path. This helper therefore explicitly reports
  **caption_only**, sends no pixels, and makes no image-analysis claim. This
  checkout has no `.env`, process model or API key. The actual deployed model's
  vision capability is unknown; even a vision model cannot analyze images through
  the current adapter. No provider request was made.
- Anay: consume prepared grounding/instructions through existing `companionInput`
  and `ChatAdapter.complete`, respecting their text/total prompt bounds. Preserve
  existing safety/refusal/help routing before ordinary conversation. Do not treat
  caption/fact/participant content as application instructions.
- Anay A05: `SessionCoordinator.submitText` owns transient history, cancellation
  and replies, but does not execute `offer_photo_conversation`. Host the selected
  photo pack and bind all opening/continuation work to the current entry. Do not
  reuse the last photo's history after Next, Just look, policy change or Stop.
- `createLocalSpeechAdapters` provides `SttAdapter.transcribe` and
  `TtsAdapter.synthesize` on the backend branch. Its handoff leaves connected mic
  capture → STT → chat → generated-speech playback/receipts pending. Reuse it;
  no second executor or browser microphone authority was introduced here.
- `ProfileDetailSchema`/`ApprovedFactSchema` and scoped PNG upload/read exist on
  the backend branch. Committed Alex fixtures have a gardening interest and generic
  garden captions/context, but no approved personal history or real photo bytes.
  Do not invent missing history or assume Alex is pictured. Host-reviewed relevance
  tags are needed when mapping approved facts to the local `PhotoStoryFact` type.
- `ActivityActionSchema` supports Talk/Next/Previous/Select/Just look/Leave. It has
  no photo-bound Repeat-last-response or continuation command. Anay/Kylie must
  agree those shared additions and browser text/capture transport. Reissuing Talk
  is not a verified Repeat. Skip may use Next/Leave; Pause/Stop remain session
  controls. Missing image/service recovery belongs to A05/A19 and Kylie's UI.

## Try the fictional rehearsal

With pinned Bun 1.4.4, from repository root:

```powershell
bun packages/activities/examples/photo-story.ts
bun test tests/photo-story.test.ts tests/reviewed-activities.test.ts
```

This machine's executable is `.tools/bun-1.4.4/bun-windows-x64/bun.exe`.
The example prints Alex's photo view, requested Talk effect, opening preparation,
fictional Roses-answer preparation, silence recovery and paused rejection. It
explicitly simulates asset-read success; it displays no actual photo and makes no
OpenRouter, STT or TTS call. It is a contract rehearsal, not an interactive chat.

The app currently hosts music only, so a full `/participant` Photo Story session
is blocked on the above dependencies. After integration, rehearse real approved
Alex media/captions → opening → explicit capture → transcript → follow-up → playback;
Repeat/Skip/Type/Just look, pause/Stop, missing media/caption, denied microphone,
unavailable AI/speech, and stale results after photo/profile/policy changes.
