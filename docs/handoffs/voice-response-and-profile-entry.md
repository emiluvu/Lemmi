# Response timing, spoken Teach Lemmi and profile entry

November 14, 2026. Branch `anay/faster-voice-entry-and-profile-flow`, based on `backend-deploy/0f299c4`. Deployment acceptance is recorded at the opening of [backend status](../backend-status.md).

## Findings and changes

- Actual public Chromium, with its own fictional profile and fixed in-memory Piper input, measured **3,193 ms** from synthetic voice end to scheduled output: **1,444 ms** before audio submission and **1,669 ms** from submission to response metadata. A separate isolated three-turn real speech/model run measured STT 343–350 ms, model 641–815 ms, TTS 148–190 ms. Its 9–10-second total included paced input/output, not just reply delay. These are individual synthetic observations, not human-room or latency percentile claims.
- Browser silence now defaults to **1,000 ms**, configurable over 1,000–8,000 ms using `PUBLIC_LEMMI_END_SILENCE_MS`; longer pauses can still be selected. A voiced frame resets the silence window. Manual Finish, initial 15-second no-speech pause, capture grants, cancellation and no-overlap rules remain. This saves 500 ms of the configured submission wait; it does not establish thought completion. Actual participant/room timing needs rehearsal.
- One family-dialogue rehearsal exposed a **20-second external model stall**. Select an **8,000 ms** private model deadline at deployment to fail explicitly sooner, with no automatic retry or fake successful reply. Keep the selected GLM model, low reasoning and 512-token limit. Normal synthesis still waits for the bounded whole reply; no streaming-STT/LLM/TTS claim.
- Actual local STT rendered the fictional name as **Lemmy** (and later **Lemme**), while the literal command matcher required **Lemmi**. Whole-command routing now accepts reviewed `Lemmi/Lemmy/Lemme/Lemi`, optional trailing `game`, polite invitations and `try/could we`. Negated, quoted and incidental mentions still do not launch activities. No fuzzy model-selected action. Optional Jev remains disabled/advisory; Stop/help/fixed concerns retain priority.
- Caregiver **Conversation** and **Photo Story** first validate/reuse the matching browser enrollment or enroll the selected fictional profile, then navigate with its ID. Failed enrollment stays in the caregiver workspace. The conversation screen has no profile selector or profile creation. Initial unselected, expired or mismatched URL entry returns to caregiver setup without setting a navigation lock. Existing locked conversations keep the exit gate; they never silently substitute another profile or bypass the code. Resource checks stay in the existing authoritative enrollment/session/database path. No migration or new public route.
- Family-location and bereavement fixed replies now acknowledge the concern and offer trusted human support. Ordinary follow-ups receive warmer system guidance. Neither path invents a relative's safety, work, whereabouts, contact, return or death. The model action guard also rejects claims of talking/speaking with someone. Quiet retains no-question policy. No private biography, new relative, contact dispatch or memory write is inferred.
